学习笔记——Swift属性

学习笔记 Swift 属性 计算属性 属性包装器
学习笔记
发布日期:   2026-07-21
更新日期:   2026-08-02
文章字数:   3.5k

属性概述

属性（Property） 将值与特定的类、结构体或枚举关联起来。Swift 中的属性主要分为两大类：

  • 存储属性（Stored Property）：把常量或变量的值存储为实例的一部分。存储属性只能由类和结构体提供。
  • 计算属性（Computed Property）：并不直接存储值，而是提供一个 getter 和一个可选的 setter，用来间接获取和设置其他属性或值。计算属性可以由类、结构体和枚举提供。

此外，还可以定义属性观察器来监控属性值的变化，用属性包装器来复用属性的存取逻辑，以及定义关联到类型本身而非实例的类型属性。

存储属性

存储属性是作为特定类或结构体实例的一部分所存储的常量或变量。存储属性可以是变量存储属性（用关键字 var 定义），也可以是常量存储属性（用关键字 let 定义）。
可以在定义存储属性的时候指定默认值，也可以在构造过程中设置和修改存储属性的初始值，甚至修改常量存储属性的值。

struct FixedLengthRange{
    var firstValue: Int
    let length: Int
}
var rangeOfThreeItems = FixedLengthRange(firstValue: 0, length: 3)
rangeOfThreeItems.firstValue = 6

常量结构体实例的存储属性

如果创建了一个结构体实例并将其赋值给一个常量，则无法修改该实例的任何属性，即使它们被声明为可变属性：

let rangeOfFourItems = FixedLengthRange(firstValue: 0, length: 4)
rangeOfFourItems.firstValue = 9
// 尽管 firstValue 是个可变属性，但这里还是会报错

这种行为是由于结构体属于值类型。当值类型的实例被声明为常量的时候，它的所有属性也就成为了常量
属于引用类型的类别则不一样，把一个引用类型的实例赋给一个常量后，依然可以修改该实例的可变属性

延时加载存储属性

延迟加载属性（Lazy Stored Properties）是指当第一次被访问时才会计算其初始值的属性。在属性声明前使用 lazy 来标示这是一个延迟加载属性。

注意
必须将延迟加载属性声明成变量（var 关键字），因为属性的初始值可能在实例构造完成之后才会得到。而常量属性在构造完成之前必须要有初始值，因此无法声明成延迟加载。

当属性的初始值依赖于外部因素，且这些因素的值在实例构造完成之后才会知道时，延迟加载属性非常有用；当获取属性的值需要复杂或大量的计算，应该采用需要时再计算的方式时，延迟加载属性也会很有用。

注意
如果一个被标记为 lazy 的属性在没有初始化时就同时被多个线程访问，则无法保证该属性只会被初始化一次。这是因为 lazy 只是延迟到首次访问才初始化的语法糖，编译器并没有为它加锁，所以在并发首次访问时会出现「检查—初始化」竞态，导致初始化闭包可能被多次执行。

计算属性

类、结构体和枚举还可以定义计算属性。计算属性不直接存储值，而是提供一个 getter 和一个可选的 setter，来间接获取和设置其他属性或变量的值。

struct Point {
    var x = 0.0, y = 0.0
}

struct Size {
    var width = 0.0, height = 0.0
}

struct Rect {
    var origin = Point()
    var size = Size()
    var center: Point {
        get {
            let centerX = origin.x + (size.width / 2)
            let centerY = origin.y + (size.height / 2)
            return Point(x: centerX, y: centerY)
        }
        set(newCenter) {
            origin.x = newCenter.x - (size.width / 2)
            origin.y = newCenter.y - (size.height / 2)
        }
    }
}

简化声明

如果计算属性的 getter 的主体是一个单一表达式，那么 getter 会隐式返回该表达式。如果计算属性的 setter 没有为要设置的新值定义名称，则默认会使用 newValue 作为名称。

struct CompactRect {
    var origin = Point()
    var size = Size()
    var center: Point {
        get {
            Point(x: origin.x + (size.width / 2), y: origin.y + (size.height / 2))
        }
        set {
            origin.x = newValue.x - (size.width / 2)
            origin.y = newValue.y - (size.height / 2)
        }
    }
}

只读计算属性

只读计算属性只有 getter，总是返回一个值，可以通过点语法访问，但不能设置为其他值。

注意
计算属性，包括只读计算属性，必须使用 var 关键字声明为变量属性，因为它们的值并非固定的。

可以通过省略 get 关键字和它的花括号来简化只读计算属性的声明。

struct Cuboid {
    var width = 0.0, height = 0.0, depth = 0.0
    var volume: Double {
        return width * height * depth
    }
}

属性观察器

属性观察器用于检测并响应属性值的变化。每次属性被设置时，无论新值是否与当前值相同，属性观察器都会被调用。
属性观察器可以添加在以下位置：

  • 自定义的存储属性
  • 继承的存储属性
  • 继承的计算属性

对于继承的属性，可以通过在子类中重写该属性来添加属性观察器。对于自定义的计算属性，应使用属性的setter来观察和响应值的变化，而不是试图创建一个观察器。
可以为属性添加以下观察器：

  • willSet：在值存储之前被调用
  • didSet：在新值存储之后立刻调用

在 willSet 中，新的属性值会作为一个常量参数传递。可以为这个参数指定名称，默认以 newValue 形式提供；同样地，didSet 中的旧属性值默认以 oldValue 提供。

注意
父类属性的 willSet 和 didSet 观察器，会在子类构造器中设置该属性值时被调用
此时父类的构造器已经执行完毕。而在构造器主体中为类的自有属性赋值时，不会调用这些观察器

观察器与 in-out 参数

将带观察器的属性作为 inout 参数传入函数时，willSet 和 didSet 总会被调用。原因是 inout 采用**复制-写回（copy-in copy-out）**模型：调用时复制属性值给参数，函数返回时再把值写回属性。这个写回等同于一次赋值，因此无论函数内部是否真的改动了值，观察器都会被触发。

in-out 参数补充

函数参数默认是常量，无法在函数内修改，且修改的只是值的拷贝、不影响外部变量。使用 inout 可让函数修改传入的变量，并让改动在函数返回后同步回外部原变量。

func doubleInPlace(_ number: inout Int) {
    number *= 2
}
var count = 10
doubleInPlace(&count) // 调用时变量前加 &
print(count)          // 20，外部变量被改变
  • 函数定义：参数类型前加 inout
  • 函数调用：变量前加 &

限制：只能传变量（var），不能传常量或字面量；不能有默认值；不能用于可变参数。

in-out 与引用类型

inout 语法上可用于引用类型（class），但要分清它改的是引用本身还是引用指向的对象：

  • 不用 inout：已经能修改对象的属性（p.name = ...），因为函数内外指向同一对象；但不能让外部变量重新指向新对象。
  • 用 inout：才能在函数内替换整个实例（p = NewObject() 或 p = nil），并让外部变量跟着指向新对象。

因此只有在需要替换整个实例时，对引用类型使用 inout 才有意义。

属性包装器

属性包装器在管理属性存储方式的代码和定义属性的代码之间添加了一层分离。要定义属性包装器，需要创建一个结构体、枚举或类，用 @propertyWrapper 标记它，并定义一个 wrappedValue 属性。

@propertyWrapper
struct TwelveOrLess {
    private var number = 0
    var wrappedValue: Int {
        get { return number }
        set { number = min(newValue, 12) }
    }
}

可以通过在属性前以特性（attribute）的形式标注包装器的名称来应用包装器。下面是一个存储矩形的结构体，使用 TwelveOrLess 属性包装器来确保其尺寸始终不超过 12：

struct SmallRectangle {
    @TwelveOrLess var width: Int
    @TwelveOrLess var height: Int
}
var rectangle = SmallRectangle()
print(rectangle.height)
// 打印 "0"。

rectangle.height = 10
print(rectangle.height)
// 打印 "10"。

rectangle.height = 24
print(rectangle.height)
// 打印 "12"。

设置被包装属性的初始值

属性包装器可以通过提供不同的构造器，支持不同的初始化写法：无参构造器对应不写初始值，init(wrappedValue:) 对应直接赋初始值，带额外参数的构造器则对应在特性后面传参。

@propertyWrapper
struct SmallNumber {
    private var maximum: Int
    private var number: Int

    var wrappedValue: Int {
        get { return number }
        set { number = min(newValue, maximum)}
    }

    init() {
        maximum = 12
        number = 0
    }

    init(wrappedValue: Int) {
        maximum = 12
        number = min(wrappedValue, maximum)
    }

    init(wrappedValue: Int, maximum: Int) {
        self.maximum = maximum
        number = min(wrappedValue, maximum)
    }
}

从属性包装器中呈现一个值

除了被包装的值外，属性包装器还可以通过定义被呈现值（projectedValue）来提供额外的功能。被呈现值的名称与被包装值相同，只是以美元符号 $ 开头。由于代码中不能定义以 $ 开头的属性，因此被呈现值不会与定义的属性产生冲突。

@propertyWrapper
struct SmallNumber {
    private var number: Int
    private(set) var projectedValue: Bool

    var wrappedValue: Int {
        get { return number }
        set {
            if newValue > 12 {
                number = 12
                projectedValue = true
            } else {
                number = newValue
                projectedValue = false
            }
        }
    }

    init() {
        self.number = 0
        self.projectedValue = false
    }
}

struct SomeStructure {
    @SmallNumber var someNumber: Int
}

var someStructure = SomeStructure()
someStructure.someNumber = 4
print(someStructure.$someNumber) // false
someStructure.someNumber = 55
print(someStructure.$someNumber) // true

被呈现值也可以直接返回包装器自身，这等于把整个包装器开放给外部使用。

全局变量和局部变量

可以将属性包装器应用于局部存储变量，但不能应用于全局变量或计算变量。

扩展
属性包装器本质上是一种语法糖，其核心提供的是将你声明的变量降级成计算属性，把真正的存储挪到 _ 前缀的变量中。而 Swift 的全局变量本质上是隐式 lazy 的，即惰性初始化：编译器不会在程序启动时求值，而是生成一个隐藏的 once 标记和一个 accessor，首次访问时通过 swift_once 线程安全地跑一次初始化。也就是说，全局变量已经具备了类似的延迟能力。

func someFunction() {
    @SmallNumber var myNumber: Int = 0
}

类型属性

实例属性是属于特定类型实例的属性。每次创建该类型的新实例时，它都有自己的一组属性值，实例之间的属性相互独立。
还可以定义属于类型本身的属性，而不是属于该类型的某个实例。无论创建多少个该类型的实例，这些属性都只有一份。

注意
与存储实例属性不同，存储类型属性必须始终指定默认值。这是因为类型本身没有构造器，无法在初始化时为存储类型属性赋值。
存储类型属性在第一次访问时会被延迟初始化。即使在多个线程同时访问时，也保证只会初始化一次，并且不需要用 lazy 修饰符标记。

类型属性语法

使用 static 关键字定义类型属性。对于类类型的计算类型属性，可以使用 class 关键字，允许子类重写父类的实现；存储类型属性只能使用 static。

class SomeClass {
    static var storedTypeProperty = "Some Value"
    static var computedTypeProperty: Int {
        return 21
    }
    class var overrideableComputedTypeProperty: Int {
        return 107
    }
}

查询和设置类型属性

类型属性也是用点语法访问的，但必须通过类型本身而不是实例来访问：

print(SomeClass.storedTypeProperty)
// 打印 "Some Value"

SomeClass.storedTypeProperty = "Another Value"
print(SomeClass.storedTypeProperty)
// 打印 "Another Value"

print(SomeClass.computedTypeProperty)
// 打印 "21"

类型属性常用于为整个类型维护共享的状态，比如配置默认值、计数器或单例：

struct AudioChannel {
    static let thresholdLevel = 10
    static var maxInputLevelForAllChannels = 0
    var currentLevel: Int = 0 {
        didSet {
            if currentLevel > AudioChannel.thresholdLevel {
                // 将新的电平值设置为阈值，避免超限
                currentLevel = AudioChannel.thresholdLevel
            }
            if currentLevel > AudioChannel.maxInputLevelForAllChannels {
                // 把当前电平记录为所有声道的最大值
                AudioChannel.maxInputLevelForAllChannels = currentLevel
            }
        }
    }
}

var leftChannel = AudioChannel()
var rightChannel = AudioChannel()

leftChannel.currentLevel = 7
print(AudioChannel.maxInputLevelForAllChannels)
// 打印 "7"

rightChannel.currentLevel = 11
print(rightChannel.currentLevel)
// 打印 "10"，被 didSet 限制在阈值
print(AudioChannel.maxInputLevelForAllChannels)
// 打印 "10"

这个例子把本文的几个知识点串在了一起：currentLevel 是带 didSet 观察器的存储属性，thresholdLevel 和 maxInputLevelForAllChannels 是类型属性，存储在类型上而非实例上，因此两个声道共用同一份数据。

小结

属性类型 存储值 可用于 关键字
存储属性 是 类、结构体 var / let
延迟存储属性 是（首次访问时） 类、结构体 lazy var
计算属性 否 类、结构体、枚举 var + get/set
类型属性 是（全类型一份） 类、结构体、枚举 static / class

几个容易踩坑的点：

  • 值类型常量实例的属性全部不可变，引用类型则不受此限制。
  • lazy 不是线程安全的，而存储类型属性的延迟初始化是线程安全的。
  • 计算属性必须用 var，即使是只读的。
  • inout 会无条件触发观察器，因为它本质是复制-写回。
