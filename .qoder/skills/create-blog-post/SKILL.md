# 创建博客文章

## 触发条件

- 用户说"创建博客"、"创建文章"、"新建文章"
- 用户说"写博客"、"发文章"、"写篇文章"
- 用户说"添加文章"、"新增文章"

## 执行流程

### 步骤 1：询问文章分类

首先询问用户文章所属的分类：

> 请告诉我这篇文章的分类是什么？（例如：AI、技术、生活、随笔等）
> 
> 现有分类：AI、学习笔记

### 步骤 2：询问文章基本信息

根据模板询问用户以下信息：

1. **title** (必填): 文章标题
2. **author** (可选，默认 DoubleR): 作者名称
3. **img** (自动生成): 封面图片路径，格式为 `/images/{文章文件名}/cover.jpg`
4. **top** (固定 false): 是否置顶——**不要询问用户**，一律填 `false`，理由见下方「置顶规则」
5. **hide** (可选，默认 false): 是否隐藏 (true/false)
6. **cover** (可选，默认 true): 是否显示封面 (true/false)
7. **password** (可选): 文章密码（如需要加密）
8. **toc** (可选，默认 true): 是否显示目录 (true/false)
9. **mathjax** (可选，默认 false): 是否启用数学公式 (true/false)
10. **summary** (可选): 文章摘要/简介
11. **tags** (可选): 文章标签，多个标签用逗号分隔

#### 置顶规则

博客的置顶位是**唯一的**，只留给学习计划总览文章：

| 文章 | top |
|------|-----|
| `source/_posts/学习笔记/学习计划-终端与AI复合型工程师成长路线.md` | `true`（长期看板，不要改动） |
| 其他所有文章 | `false` |

新建文章时不询问置顶、不主动置顶。若用户明确要求置顶某篇新文章，需提示「这会与学习计划总览争抢置顶位」并确认后再改。

### 步骤 3：创建文件夹结构

1. 检查 `source/_posts/{分类}/` 文件夹是否存在，不存在则创建
2. 检查 `source/images/{文章文件名}/` 文件夹是否存在，不存在则创建

### 步骤 4：生成文章文件

在 `source/_posts/{分类}/{文章标题}.md` 创建文章，Front-matter 格式如下：

```yaml
---
title: {用户输入的标题}
date: {当前时间，格式 2026-02-12T20:41:00}
author: {用户输入的作者，默认 DoubleR}
img: /images/{文章文件名}/cover.jpg
top: false
hide: {true/false，默认 false}
cover: {true/false，默认 true}
password: {用户输入的密码，可选}
toc: {true/false，默认 true}
mathjax: {true/false，默认 false}
summary: {用户输入的摘要，可选}
categories: {分类}
tags:
  - {标签1}
  - {标签2}
---
```

### 步骤 5：创建图片素材文件夹并复制封面图片

1. 在 `source/images/{文章文件名}/` 创建文件夹，用于存放文章中的图片素材
2. 检查 `~/Pictures/博客文章封面/` 文件夹是否存在图片：
   - 如果不存在或为空，提示用户手动准备封面图片
   - 如果存在图片，按修改时间排序选择最新的一张图片
3. **后台复制图片**：使用后台进程将选中的图片复制到 `source/images/{文章文件名}/cover.jpg`，不等待命令完成
4. **删除原图片**：复制完成后，删除 `~/Pictures/博客文章封面/` 中的原图片，确保后续不会重复使用
5. 记录使用的封面图片信息

**注意**：复制和删除操作使用后台进程执行（`is_background: true`），不阻塞主流程

### 步骤 6：返回结果

告知用户文章创建成功，并显示：
- 文章完整路径
- 图片素材文件夹路径
- 封面图片信息（从 `~/Pictures/博客文章封面/` 复制的原文件名）
- 剩余可用封面图片数量

## 学习笔记类文章规范

当文章属于学习计划体系（用户提到「学习笔记」、「S1/S2 节次」、「主题 01」等）时，走本节的固定规范，**不再逐项询问元数据**。

### 命名与元数据

| 项目 | 规范 |
|------|------|
| 文件路径 | `source/_posts/学习笔记/学习笔记-{主题关键词}.md` |
| front-matter title | `学习笔记——{主题关键词}`（正文标题用中文破折号，文件名用连字符） |
| categories | `学习笔记` |
| tags | `学习笔记` + 3-4 个主题标签（如 Swift、闭包、捕获列表、逃逸闭包） |
| top / mathjax | `false` / `false`（含数学公式时才开 mathjax） |
| toc | `true` |
| summary | `主题 NN「{主题名}」SN 节次学习笔记，梳理 {知识点1}、{知识点2}……` |

注意 `permalink: :year/:month/:day/:title/` 中的 `:title` 取的是**文件名**而非 front-matter 的 title，链接里出现的是 `学习笔记-Swift闭包与捕获语义`。

### 骨架结构

知识点组织方式：**h1 = 一个知识点，h2 = 该知识点的细分**，与既有笔记形态一致。固定顺序：

```markdown
## 本节定位          <- 表格：所属单元 / 所属节次 / 主资料 / 本节产出
**对应 Checklist 条目**  <- 无序列表，从 学习计划/知识点Checklist.md 原文照抄条目

# {知识点 1}         <- 每个知识点一个 h1，顺序对齐主题文件里该节次的资料小节
## {细分小节}
# {知识点 2}
...
# 验证理解：{N} 段 Playground 代码   <- 对应主题文件里该节次的「验证理解」要求
# 小结
# 扩展阅读            <- 主资料链接 + 延伸书目
```

`本节定位` 与 `对应 Checklist 条目` 两块是给 `track-learning-progress` 用的映射依据，**必须写**，条目文字要与 `学习计划/知识点Checklist.md` 中一致，不要改写。

### 只生成骨架时（用户说「不需要包含具体内容」）

- 只输出标题层级，正文留空
- 每个小节下用 **HTML 注释** 写写作要点（`<!-- ... -->`），它在编辑器里可见、渲染时不输出，用户写完删不删都不影响发布；**不要**用 `> 待写` 这类可见占位符
- 文首用一段 HTML 注释说明「本文是 SN 交付物，每个 h1 至少要有原理解释 + 可运行代码」
- 交付时提醒：标注「能手写」的知识点必须贴完整可运行代码，否则进度追踪只会判 🟡（部分覆盖）而不勾选

验证注释未泄漏到页面：

```bash
cd /Users/zhujialei/Documents/blog && npx hexo generate
grep -c "写作提示" "public/{permalink路径}/index.html"   # 应为 0
```

### 与进度追踪的衔接

笔记写完后由 `track-learning-progress` 读取并判定：有独立小节 + 原理/代码/推导 + 小结自己归纳 → 🟢 勾选；仅段落提及 → 🟡 待补。骨架阶段就按这个标准布局，能避免后续判定为部分覆盖。

## 技术实现说明

### 图片复制和删除的后台执行

复制封面图片和删除原图片的操作使用后台进程执行：

```json
{
  "command": "cp ~/Pictures/博客文章封面/{图片名}.jpg /Users/zhujialei/Documents/blog/source/images/{文章文件名}/cover.jpg",
  "is_background": true
}
```

删除原图片（在复制命令之后执行）：

```json
{
  "command": "rm ~/Pictures/博客文章封面/{图片名}.jpg",
  "is_background": true
}
```

### 剩余图片数量统计

统计剩余可用封面图片数量：

```bash
ls ~/Pictures/博客文章封面/*.jpg 2>/dev/null | wc -l
```
