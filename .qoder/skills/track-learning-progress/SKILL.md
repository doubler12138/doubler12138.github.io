# 追踪学习进度

把「写完一篇学习笔记」变成「一次进度同步」：读笔记 → 判定掌握程度 → 更新五处文档。核心原则是**有证据才勾选**——笔记里讲清楚了才算掌握，不靠猜。

## 触发条件

- **笔记驱动（主路径）**：用户说"我写完了这篇学习笔记，更新一下进度"、"根据 XXX 笔记更新学习进度"，通常会附带一个笔记文件路径或 `@` 引用
- **口头汇报**：用户说"S1 学完了"、"A1 单元完成"、"掌握了 XXX 知识点"、"打卡"
- **仅同步**：用户说"同步学习计划博客"、"更新一下进度视图"

## 文档地图（六处联动）

| 文件 | 职责 | 本 Skill 的更新内容 |
|------|------|--------------------|
| `学习计划/核心能力图谱.md` | 能力基准线 | **只读**，不修改（除用户明确要求调整能力域） |
| `学习计划/知识点Checklist.md` | 270 项原子知识点 | 勾选条目 + 重算「进度总览」表 |
| `学习计划/progress.md` | 单元级进度总账 | 单元状态/掌握度/累计耗时/最后学习 + 调整日志 + 复习待办 |
| `学习计划/主题NN-*.md` | 当前主题节次拆解 | 节次状态、里程碑勾选、实际产出补记 |
| `source/_posts/学习笔记/学习计划-终端与AI复合型工程师成长路线.md` | 对外统一视图（博客） | 顶部摘要行、总览表、模块进度表、主题节次表、调整日志、复习待办、**学习笔记归档表**、Checklist 勾选与分域计数 |
| `source/_posts/学习笔记/{笔记}.md` | 本次学习的交付物 | **只读**，作为判定依据 |

> 四份计划文档在 `学习计划/` 目录下（不在仓库根目录）；博客文章在 `source/_posts/学习笔记/`。

## 模式 A：笔记驱动更新（主路径）

### A1. 确定笔记文件

- 用户已指定路径或 `@` 引用 → 直接使用
- 未指定 → 列出候选让用户确认：

```bash
ls -t source/_posts/学习笔记/*.md | head -5
```

⚠️ **必须排除** `学习计划-终端与AI复合型工程师成长路线.md`——它是进度视图本身，不是学习笔记。

### A2. 解析笔记内容

读取笔记全文，提取以下信号：

| 信号 | 提取方式 | 用途 |
|------|----------|------|
| Front-matter | `title` / `date` / `tags` / `summary` | 判断主题归属、生成归档链接 |
| 标题树 | `grep -n '^#\{1,3\} ' 笔记路径` | h1/h2 是知识点的主骨架 |
| 代码示例 | 统计 ` ``` ` 代码块数量与语言 | 判定「能手写」的证据 |
| 推导/图示 | 公式、图片引用、表格 | 判定「能讲清原理」的证据 |
| 小结段落 | 「小结」「总结」章节 | 判断是否形成自己的理解 |
| 篇幅 | `wc -m` 字数 | 辅助估算耗时（仅作参考） |

笔记的典型形态：标题为「学习笔记——XXX」，每个 h1 对应一个知识点，h2/h3 是细分，末尾有「小结」与「扩展阅读」。

### A3. 判定掌握档位（核心判断规则）

对笔记涉及的每个知识点，逐一对照 `学习计划/知识点Checklist.md` 的条目，判定为三档之一：

| 档位 | 判定信号 | 动作 |
|------|----------|------|
| 🟢 **已掌握** | 笔记中有**独立小节**（h1/h2）系统讲解，且具备原理解释、代码示例或推导过程之一，并在小结中有自己的归纳 | 勾选 `[x]（日期）` |
| 🟡 **部分覆盖** | 仅在段落中被提及、只罗列了 API 用法、没有原理解释也没有示例 | **不勾选**，列入「待补清单」并说明缺什么 |
| 🔴 **未涉及** | 笔记中没有出现 | 不动 |

**分类型加严规则**（对齐 Checklist 的深度要求）：

- 条目标注「**能手写**」（如快排手写、AnyEraser、LRU、属性包装器）→ 笔记中必须有**可运行的完整代码**，否则最多 🟡
- 条目标注「**能讲清 / 能推导 / 能画出来**」→ 必须有原理性解释或推导步骤，只有结论性描述判 🟡
- 条目标注「**了解**」→ 有准确的概念性描述即可判 🟢
- 条目含「**动手**」（如搭建 RAG demo、实现小型 Agent）→ 必须有实际产物（仓库路径/截图/运行结果），笔记里只有设计思路判 🟡

**禁止行为**：

- 不因为"这一节应该覆盖这些点"就把同节次的其他条目一起勾上——只勾笔记里真有证据的
- 不因为笔记标题宽泛（如「Swift 属性」）就勾选整个能力域下的相关条目
- 已是 `[x]` 的条目不重复勾选、不覆盖原有日期

### A4. 输出映射表并等待确认

写入前**必须**先给用户这张表，等确认后再改文件：

```text
笔记：学习笔记——Swift属性（2026-08-10）
归属：主题01 Swift 基础进阶 · 疑似跨节次（S1 闭包相关 1 项）

| Checklist 条目 | 证据（笔记章节） | 档位 | 动作 |
|----------------|------------------|------|------|
| 属性包装器 @propertyWrapper（能手写一个） | 「属性包装器」含完整代码 | 🟢 | 勾选 |
| KeyPath 与 @dynamicMemberLookup | 「类型属性」中一句提及 | 🟡 | 待补：缺 KeyPath 用法与原理 |

计划外内容：「延时加载存储属性 lazy」——Checklist 中无对应条目
耗时：笔记 6200 字 + 5 段代码，估 90min（请确认实际耗时）
```

同时明确询问缺失字段：**实际耗时**；若本次导致单元完成，还要问**掌握度 1-5**。

### A5. 处理计划外知识点

笔记覆盖了 270 项之外的内容时，**不擅自新增 Checklist 条目**（会破坏 270 的分域计数基线）。列出后询问用户二选一：

- **(a) 补入 Checklist**：追加条目到对应能力域 → 同步更新该域条目数、合计总数（270 → N）、博客第五章标题与各处分母，并在 `核心能力图谱.md` 对应能力项补一行
- **(b) 仅记录**：写入 `progress.md` 调整日志，Checklist 不变

### A6. 推断节次与单元归属

用笔记 `tags` + 标题树去匹配 `学习计划/主题NN-*.md` 的节次知识点列：

- 命中某一节次 → 该节次可勾选（前提：该节次涉及的条目多数判 🟢）
- 跨多个节次 → 全部标出，只勾选证据充分的那些
- 与当前进行中主题无关（如写了算法笔记但主题是 Swift）→ 不改主题文件，只更新 Checklist 与对应单元的「最后学习/累计耗时」，并在汇总中提示"本次学习偏离当前主题"

### A7. 执行写入

按「更新规则」章节依次更新：知识点 Checklist → progress.md → 主题文件 → 博客文章（含**学习笔记归档表**）。

归档表新增一行，笔记链接按 `_config.yml` 的 `permalink: :year/:month/:day/:title/` 规则生成：

```text
| [学习笔记——Swift属性](https://doubler12138.github.io/2026/08/10/学习笔记——Swift属性/) | 2026-08-10 | 主题01 S2 | 属性包装器、计算属性、属性观察器 |
```

日期取笔记 front-matter 的 `date`，标题段取**文件名**（Hexo 的 `:title` 用的是文件名，不是 front-matter 的 title）。首次写入时删除表中的「暂无」占位行。

## 模式 B：口头汇报更新

用户没有笔记、直接汇报进度时使用。从自然语言中提取：

| 字段 | 缺失时的处理 |
|------|-------------|
| 完成范围（节次 S1/单元 A1） | 默认当前进行中主题的下一个未完成节次 |
| 掌握的知识点 | 按节次覆盖范围推断，**列出待勾选清单让用户确认** |
| 耗时 | 不填则累计耗时不变 |
| 掌握度 1-5 | 单元完成时必须询问；节次完成不需要 |
| 日期 | 默认当天 |

如果用户只说"更新一下进度"而无任何具体信息，**先反问**完成了什么，不要凭空勾选。

## 更新规则

### 步骤 1：知识点 Checklist

1. `- [ ] XXX` → `- [x] XXX（YYYY-MM-DD）`
2. 重算「进度总览」表：各能力域「已掌握」计数与「进度」列
3. 进度条：10 格，`▓` 已完成 / `░` 未完成，填充格数 = `round(百分比 / 10)`，百分比取整
   - 示例：41 项掌握 12 项 → 29% → `▓▓▓░░░░░░░ 29%`
4. 更新「合计」行

### 步骤 2：progress.md

1. 单元行：状态（`未开始`→`进行中`→`已完成`）、掌握度（单元完成时填 1-5）、累计耗时（累加，格式 `40min`/`2.5h`）、最后学习日期
2. 顶部 `> 最近更新：YYYY-MM-DD`
3. 调整日志：仅结构性变化时追加（单元完成、主题切换、计划调整、Checklist 扩容）；单纯节次打卡不写
4. 复习待办：单元变「已完成」时注入 `+7 天`（首次复习）与 `+30 天`（二次复习）两条；复习完成后移除并记入调整日志

### 步骤 3：主题文件

1. 节次状态 `[ ]` → `[x]`
2. 补记实际产出（笔记链接、Playground/demo 路径）
3. 里程碑达成项勾选
4. 全部节次完成 → 主题状态改「已完成」，按《核心能力图谱》三阶段顺序建议下一主题，并询问是否创建 `学习计划/主题NN+1-xxx.md`

### 步骤 4：博客文章（七处，逐一核对）

1. 顶部摘要行：`最近更新`、`总进度：X / 270（Y%）`、`当前主题`
2. 第四章「总览」表：知识点掌握（含进度条）、单元完成 X / 31、进行中主题、累计学习时长
3. 模块进度表：`⚪ 未开始` / `🔵 进行中` / `✅ 已完成`
4. 进行中主题区块：节次表状态列（`⬜` / `✅`）、里程碑勾选、主题元信息表
5. 调整日志 + 复习待办：与 progress.md 一致
6. **学习笔记归档表**：追加本次笔记行
7. 第五章 Checklist：勾选条目 + 各 `### 能力X：... · N / M` 标题中的已掌握数

⚠️ 不要修改 Front-matter 的 `date`（发布日期保持不变）。

### 步骤 5：一致性校验（必须执行）

```bash
cd /Users/zhujialei/Documents/blog
# 计划文档：总条目应恒为 270（除已确认扩容），已勾选数应与总览表一致
grep -c '^- \[' 学习计划/知识点Checklist.md
grep -c '^- \[x\]' 学习计划/知识点Checklist.md
# 博客：分域条目数与标题中的分母核对（应为 41/64/31/26/22/33/40/13）
awk '/^### 能力/{s=$0} /^- \[/{c[s]++} END{for(k in c) print c[k], k}' \
  "source/_posts/学习笔记/学习计划-终端与AI复合型工程师成长路线.md"
```

两侧已勾选数必须相等；博客分域条目数必须与标题分母一致。不一致说明误改，需修正后再汇报。

### 步骤 6：汇总并询问是否发布

输出变更摘要：勾选条目（逐条）、🟡 待补清单、单元/节次状态变化、总进度（旧 → 新）、新增复习待办、下一步建议。

然后询问**是否发布博客更新**；确认后交由 `publish-blog-post` Skill 处理（本 Skill 不执行 `hexo deploy`）。

## 速查表

### 状态取值

| 场景 | progress.md | 博客 | 主题文件节次 |
|------|-------------|------|-------------|
| 未开始 | `未开始` | `⚪ 未开始` | `[ ]` |
| 进行中 | `进行中` | `🔵 进行中` | `[ ]` |
| 已完成 | `已完成` | `✅ 已完成` | `[x]` |

### 掌握度语义（1-5）

| 分值 | 含义 |
|------|------|
| 1 | 只有印象，看到能认出 |
| 2 | 能说出概念，讲不清原理 |
| 3 | 能讲清原理，实践较少 |
| 4 | 能讲清 + 能手写 / 能应用 |
| 5 | 能讲清设计取舍，能教别人、能应对追问 |

单元完成最低标准 **3 分**；低于 3 分建议保持「进行中」并补学。

### 幂等与安全

- 每次编辑前先读取最新内容（未读直接替换会失败）
- 不删除历史记录（调整日志、已勾选条目、已完成节次、归档行）
- 只改与本次相关的行，不重排、不重写整份文档
- 判定存疑时列入 🟡 并询问，宁可漏勾不可错勾
