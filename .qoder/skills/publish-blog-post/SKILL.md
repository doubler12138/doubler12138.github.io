# 发布博客文章

## 触发条件

- 用户说"推送最新文章"、"发布最新文章"
- 用户说"deploy文章"、"部署文章"
- 用户说"发布博客"、"deploy博客"
- 用户说"检查文章"、"优化文章"

## 执行流程

### 步骤 1：定位最新文章

1. 扫描 `source/_posts/` 目录下的所有文章文件（包括子目录）
2. 根据文件的 **修改时间** 找出最新创建或修改的文章
3. 读取文章内容，向用户确认是否是这篇文章：
   > 找到最新文章：`{分类}/{文章标题}.md`
   > 
   > 是否对这篇文章进行处理？（是/否）

### 步骤 2：错别字检查与修正

1. 仔细阅读文章内容
2. 识别并列出发现的错别字、语法错误、标点符号问题
3. 向用户展示发现的问题及修改建议：
   > **发现以下错别字/语法问题：**
   > - 第X行："{原文}" → 建议改为 "{修正}"
   > - ...
   > 
   > 是否自动修正以上问题？（是/否/部分修正）
4. 根据用户确认执行修改

### 步骤 3：图片路径检查与修正

1. 扫描文章中的图片引用（包括 Markdown 格式 `![alt](path)` 和 HTML `<img>` 标签）
2. 检查 Front-matter 中的 `img` 字段
3. 验证图片路径是否符合规范：
   - 文章内图片路径应为：`/images/{文章文件名}/{图片名}.{扩展名}`
   - 封面图片路径应为：`/images/{文章文件名}/cover.jpg`
4. 检查实际图片文件是否存在于 `source/images/{文章文件名}/` 目录
5. 向用户报告问题：
   > **图片路径检查结果：**
   > - ✅ 路径正确：{图片路径}
   > - ❌ 路径错误：{图片路径} → 建议改为：{正确路径}
   > - ⚠️ 图片文件不存在：{图片路径}
   > 
   > 是否自动修正路径问题？（是/否）
6. 根据用户确认执行修改

### 步骤 4：内容专业检查、优化建议与 Tags 推荐

1. 以专业视角分析文章内容：
   - **技术准确性**：检查概念、术语使用是否准确
   - **逻辑结构**：检查文章结构是否清晰、逻辑是否通顺
   - **表达优化**：检查是否有更简洁、准确的表达方式
   - **格式规范**：检查 Markdown 格式是否规范
2. 向用户展示优化建议：
   > **内容优化建议：**
   > 
   > 1. **技术准确性**
   >    - 第X行："{内容}" 建议修改为 "{建议}"，因为 {原因}
   > 
   > 2. **逻辑结构**
   >    - 建议在某处添加过渡段落
   >    - 某部分内容可以前置/后置
   > 
   > 3. **表达优化**
   >    - 第X行：可以简化为 ...
   > 
   > 4. **格式规范**
   >    - 代码块建议添加语言标识
   >    - 标题层级建议调整
   > 
   > 是否应用以上优化？（全部应用/部分应用/跳过）
3. 根据用户选择执行修改

4. **Tags 标签推荐**：
   基于文章主题和内容分析，推荐以下 3-5 个标签：
   > **推荐标签：**
   > - `{标签1}` - {推荐理由}
   > - `{标签2}` - {推荐理由}
   > - `{标签3}` - {推荐理由}
   > - `{标签4}` - {推荐理由}
   > - `{标签5}` - {推荐理由}
   > 
   > 当前文章标签：{现有标签列表}
   > 
   > 是否更新文章标签？
   > - 输入 `是`：使用推荐标签替换现有标签
   > - 输入 `添加`：将推荐标签添加到现有标签
   > - 输入 `自定义`：手动输入标签（用逗号分隔）
   > - 输入 `否`：保持现有标签不变
5. 根据用户选择更新文章的 `tags` 字段

### 步骤 5：扩展学习资源推荐

1. 根据文章主题，搜索相关的优质学习资源：
   - 官方文档
   - 技术博客
   - 教程文章
   - GitHub 仓库
2. 整理推荐内容：
   > **扩展学习资源推荐：**
   > 
   > 基于文章主题「{主题}」，推荐以下学习资源：
   > 
   > 1. **官方文档**
   >    - [{标题}]({URL}) - {简介}
   > 
   > 2. **技术博客**
   >    - [{标题}]({URL}) - {简介}
   > 
   > 3. **实践教程**
   >    - [{标题}]({URL}) - {简介}
   > 
   > 4. **延伸阅读**
   >    - [{标题}]({URL}) - {简介}
   > 
   > 是否将这些资源添加到文章末尾作为「扩展阅读」？（是/否/选择性添加）
3. 根据用户选择，在文章末尾添加扩展阅读章节

### 步骤 6：本地预览（可选）

在所有检查和优化完成后，询问用户是否需要本地预览：

> **所有检查与优化已完成！**
> 
> 是否需要先进行本地预览，确认效果后再部署？
> 
> - 输入 `是`：启动本地服务器，打开浏览器访问 http://localhost:4000
> - 输入 `否`：直接进行部署
> - 输入 `跳过`：跳过预览和部署，保存修改即可

如用户选择预览：
1. 执行 `npm run clean` 清理旧构建
2. 执行 `npm run build` 生成静态站点
3. 后台执行 `npm run server` 启动本地服务器
4. 打开浏览器访问 `http://localhost:4000`
5. 提示用户：
   > 本地预览已启动，浏览器正在打开 http://localhost:4000
   > 
   > 请检查文章显示效果，确认无误后告诉我「部署」继续发布，或「停止」结束预览

如用户确认部署或选择直接部署，进入步骤 7

### 步骤 7：生成与部署

1. 如从预览步骤进入，询问确认：
   > 确认部署文章到 GitHub Pages？（是/否）

2. 如用户确认，依次执行：
   ```bash
   npm run clean
   npm run build
   npm run deploy
   ```

3. 部署完成后报告结果：
   > ✅ 部署成功！
   > 
   > 文章已发布至：https://doubler12138.github.io
   > 
   > 更新内容摘要：
   > - 修正了 X 处错别字
   > - 修复了 X 处图片路径
   > - 优化了 X 处内容
   > - 更新了文章标签
   > - 添加了 X 条扩展资源

## 注意事项

1. **每一步修改前都需要用户确认**，不要自动修改
2. **图片路径规范**：
   - 文章文件名为 `文章标题.md`
   - 对应图片文件夹为 `source/images/文章标题/`
   - 封面图片固定为 `cover.jpg`
3. **扩展资源推荐要相关且优质**，优先选择官方文档和知名技术博客
4. **Tags 推荐原则**：
   - 标签应与文章主题高度相关
   - 优先使用博客中已存在的标签，保持标签体系统一
   - 标签数量建议 3-5 个，不宜过多
   - 标签应覆盖文章的核心概念、技术栈、应用场景
5. **部署前确保所有修改已保存**
6. **本地预览注意事项**：
   - 预览服务器在后台运行，可通过 `Ctrl+C` 停止
   - 预览模式下修改文章后需要刷新浏览器查看效果
   - 确认效果后输入「部署」继续发布流程
